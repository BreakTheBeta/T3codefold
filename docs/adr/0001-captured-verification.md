# Keep captured verification separate from review judgment

GLaDOS accepted agent-reported evidence without execution receipts. Fold's work subsystem now captures checks against a task's selected, user-approved evidence profile, binding the result to its subject, acceptance criteria and profile version. A subject can be a commit, a file digest or an observation of a named host target. Provider adapters remain unaware of verification policy. A lead's review remains distinct because executing a recipe cannot establish its adequacy, musical taste or product quality.

Profiles belong to projects, but selection belongs to tasks: the same project can contain coding, research and operational work. Legacy project recipes remain defaults. Leads may select approved profiles before attempts; subsequent changes and opting into reported evidence require the user. Selection changes advance criteria and invalidate previous acceptance. Profile edits invalidate only tasks using that profile. The run snapshots the selected profile, and evidence survives subsequent revisions.

Code runs in a disposable clone. Artifact checks receive one content-identified file in a temporary directory; research can use a source-bound packet and audio can use a render. Observations run in the project workspace on an explicitly approved environment and target, with an effect policy and mandatory freshness limit. These are approved host commands, not a security sandbox: observe-only is a command contract, not enforced OS isolation. Readiness must establish required tools, hardware and services; an unavailable environment or failed readiness is inconclusive. No automatic cross-environment dispatch is implied.

Evidence and bounded attachments survive temporary-directory cleanup. Artifact checks reject input changes during execution. Observation receipts record target, environment, interval and optional configuration digest; freshness begins when execution starts, and expired evidence cannot authorize acceptance. A historical acceptance is not continuous monitoring. An agent reviewing an observation must review after the captured result. Restart never automatically repeats a started run, because commands may have produced external effects.

The serial runner reuses process, work-journal and authenticated attachment services. Integration with upstream remains runtime registration and client entry points, rather than provider-specific workflows. See the [portfolio design](../internals/glados/work-outcomes.md) for the outcome-specific trade-offs and limits.
