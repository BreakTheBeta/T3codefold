# Decisions wait; coordination continues

A user question belongs to the affected task, not to the lifetime of GLaDOS's conversation. Otherwise a soundtrack choice in dynoGen can prevent GLaDOS from reviewing a game fix or managing the house project. This adopts [pstack PS-032](pstack.md#ps-032--explicit-human-gates-without-stopping-unrelated-work) and [Gas City GC-006](gas-city.md#gc-006--dependency-readiness-is-derived-state): park the unit of work, preserve its context, and keep independent work eligible.

The decision lives in the existing GLaDOS work domain, below the provider adapters. `request-decision` and `resolve-decision` use the same typed work-command contract through MCP, CLI and clients. The pure [decider](../../../apps/server/src/pitboss/Work.ts) records the question, options, recommendation and eventual answer. The existing SQLite work journal, snapshot and outbox persist the transition together. No new global approval queue or provider-specific scheduler is introduced.

A pending decision blocks assignment, acceptance and reopening of that task. Its current worker receives a durable stop request; other workers and the elected role are unchanged. The worker continues occupying capacity until its stop is observed, so an unavailable provider cannot cause overlapping writers. Existing dependency readiness keeps dependent tasks waiting. Cancellation remains available. Acknowledging a notification does not answer the question, and recommendations never become approval through a timeout.

Only a user can resolve the gate at the task's home environment. An answer queues the task for its manager to reconcile within existing permissions, model policy and retry limits; it does not automatically launch work or authorize a leadership change. Retained candidate work remains available through the existing resume path. The answer is injected into subsequent worker assignment context. Coordinator and lead prompts instruct agents to record task questions here, work around them, and finish idle turns so normal runtime wakeups can deliver new work and answers.

This distinction has a limit: a provider-native approval already blocking a running coordinator is still owned by that provider. This protocol avoids using those blocking calls for product decisions; it does not bypass tool permissions or forcibly resume an unrelated approval.

Mobile presents the same records in a decision inbox, with a single list/detail flow on narrow windows and simultaneous panes on wide windows. Window size controls presentation, never task ownership, so folding does not send, discard or answer a decision. Web and desktop resolve the same gate. Remote tasks retain their home authority; answering a task decision cannot elect a shared leader.
