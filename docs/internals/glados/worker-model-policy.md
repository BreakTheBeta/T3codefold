# Worker model choices and routing

GLaDOS needs a small set of usable worker choices and guidance about when to use them. A retry count does not establish that a different model is appropriate. The design therefore separates user-authorized model choices from the coordinator's task-by-task judgment. This is the adaptation of Gas City's role defaults and explicit task overrides, rather than a claim that Gas City ships an automatic expensive-to-cheap model hierarchy.

## What T3 actually exposes

T3's canonical `ModelSelection` contains `instanceId`, `model`, and optional `options: [{ id, value }]`. An instance identifies configured routing and credentials; the same driver or model name on two environments does not establish interchangeable access. Option descriptors are provider/model capabilities, including select choices and booleans. There is no universal thinking-level enum that a second settings UI should invent. See [ModelSelection](../../../packages/contracts/src/modelSelection.ts) and [provider options](../../../packages/contracts/src/model.ts).

The agent can discover a selected destination through `orchestrator_capabilities({ environmentId, projectId })`, including provider instances, models and option descriptors. `t3_environment_list` describes environments reachable through connected clients; reachability alone does not establish durable peer coordination authority. `delegate_task` creates an app-owned child, while `t3_thread_start` creates an ordinary independent thread. Their target overrides use `providerInstanceId`, model and options. GLaDOS's tracked task API separately accepts `work_command` with `assign.model: ModelSelection`; it records an attempt and launches through the shared `ThreadLaunchService`. These are related APIs, not interchangeable task ledgers. See [MCP contracts](../../../packages/contracts/src/orchestratorMcp.ts), [tool semantics](../../../apps/server/src/mcp/toolkits/orchestrator/tools.ts), [work contract](../../../packages/contracts/src/pitboss.ts), and [launch service](../../../apps/server/src/orchestration-v2/ThreadLaunchService.ts).

Native UI building blocks already exist: `ProviderModelPicker` accepts entries and model catalogs for one environment; `deriveProviderInstanceEntries`, `applyProviderInstanceSettings`, and `getAppModelOptionsForInstance` retain configured instance identity and availability. `TraitsPicker` renders the model's option descriptors, with controlled `onModelOptionsChange`. The shared helpers `getProviderOptionDescriptors` and `buildExplicitProviderOptionSelectionsFromDescriptors` translate displayed selections to dispatch options. For a saved worker profile, disable prompt-injected effort so selecting thinking does not silently edit an unrelated conversation prompt. See [picker](../../../apps/web/src/components/chat/ProviderModelPicker.tsx), [traits](../../../apps/web/src/components/chat/TraitsPicker.tsx), [instance catalog](../../../apps/web/src/providerInstances.ts), [model settings](../../../apps/web/src/modelSelection.ts), and [shared options](../../../packages/shared/src/model.ts).

## Design decision

The brief has a default `workerModel`, an optional `alternateWorkerModel`, and `modelGuidance`. Each choice carries its native thinking/options selection. GLaDOS chooses an allowed model explicitly for a task; omission uses the default. The alternate is an available choice, not a retry ladder. Users can describe which work suits each model without a maintained global price or intelligence ranking. The guidance should encourage small assignments, concrete verification, and escalation supported by evidence rather than escalation merely because an attempt number increased.

The initial concurrency default is ten workers. Capacity and attempt limits remain admission rules in the task engine. Model guidance and chosen thinking levels steer the coordinator; supported option validation belongs at the provider boundary. Allowed model identities constrain agent/peer assignments, while a thinking default is not a rigid ceiling on supported options. This is not a general process sandbox or a global spend limit. See the current [brief and assignment schemas](../../../packages/contracts/src/pitboss.ts) and [work admission/context](../../../apps/server/src/pitboss/Work.ts) for implementation, which remains the source of truth as this decision evolves.

Catalogs must come from the environment that will execute the task. A disconnected or removed instance stays visibly unavailable; never silently replace it with a same-driver account. Connected environments can be selected for management, but that selection does not grant coordination authority. In the current peer protocol, work executes at its fixed task home, using that home's brief/model choices unless an explicit compatible choice is admitted there. Another host's local provider identifiers must not be copied into that home by assumption. See [peer protocol](../../../apps/server/src/pitboss/PeerService.ts) and [pilot scope](scope.md).

## Gas City evidence

Static inspection used Gas City `36763a969ea31d524386b4dfee514e76a1a731b4` and its pinned Gastown pack `33d3a430a67d1782ad364556cb566bdb01d0afe3`. These findings describe those revisions, not a live runtime benchmark or current pricing:

- **Implemented defaults:** schema defaults merge with provider options and then agent options. Provider schema validation determines legal choices. This supports distinct role profiles. [ComputeEffectiveDefaults and ResolveOptions](https://github.com/gastownhall/gascity/blob/36763a969ea31d524386b4dfee514e76a1a731b4/internal/config/options.go#L38).
- **Implemented task overrides:** current work beads can carry `opt_model`, `opt_effort`, or other declared options. The resolver validates these against the resolved provider schema; invalid values are ignored with a log entry. Launch applies task choices with explicit session choices retaining precedence. This is launch-time routing, not proof of automatic per-task model switching in an already running process. [Task resolver](https://github.com/gastownhall/gascity/blob/36763a969ea31d524386b4dfee514e76a1a731b4/cmd/gc/session_reconciler.go#L6131), [launch precedence](https://github.com/gastownhall/gascity/blob/36763a969ea31d524386b4dfee514e76a1a731b4/cmd/gc/session_lifecycle_parallel.go#L999).
- **Prompt guidance:** the mayor prefers dispatch to polecats to retain coordination context, but permits quick direct work when that is faster. This is a responsibility/context policy, not a measured cost hierarchy. [Mayor work philosophy](https://github.com/gastownhall/gascity-packs/blob/33d3a430a67d1782ad364556cb566bdb01d0afe3/gastown/agents/mayor/prompt.template.md#L13).
- **Shipped configuration:** the example inherits Claude; the pinned mayor and polecat configurations do not prescribe different worker models. A hierarchy of roles is not evidence of a hierarchy of model prices. [Example](https://github.com/gastownhall/gascity/blob/36763a969ea31d524386b4dfee514e76a1a731b4/examples/gastown/city.toml#L24), [mayor configuration](https://github.com/gastownhall/gascity-packs/blob/33d3a430a67d1782ad364556cb566bdb01d0afe3/gastown/agents/mayor/agent.toml), [polecat configuration](https://github.com/gastownhall/gascity-packs/blob/33d3a430a67d1782ad364556cb566bdb01d0afe3/gastown/agents/polecat/agent.toml).
- **Configuration trap:** `[agent_defaults].model` is explicitly documented in source as parsed/composed but not automatically applied at runtime. The implemented option-default seam is the useful inspiration. [AgentDefaults](https://github.com/gastownhall/gascity/blob/36763a969ea31d524386b4dfee514e76a1a731b4/internal/config/config.go#L3057).

The important borrowing is explicit, capability-aware dispatch with a durable record of the choice. Verification supplies the evidence for changing that choice; neither a prompt nor an attractive dropdown guarantees successful work.
